# TechO Search MVP v0.2 — 構成・修正点・マッチングロジック・出典表示

## 1. 起動方法
```bash
pip install -r requirements.txt
streamlit run app.py
```
- 初回起動時にデモ用の過去案件20件（架空）が自動で入ります
- 外部APIに接続できない環境では「提案材料」タブで「デモデータ」を選ぶと画面確認できます
- **公開前に `config.py` の `ORG_NAME`（加工の主体）を実際の社名・チーム名に変更してください**

## 2. ファイル構成
| ファイル | 役割 |
|---|---|
| `app.py` | 画面（5タブ） |
| `config.py` | 8大項目・政策キーワード辞書・スコア重み・**出典表示の文言** |
| `schema.sql` / `database.py` | SQLite（cases / FTS5 / ext_docs / search_logs） |
| `ranking.py` | 類似案件検索（TF-IDF＋コサイン類似度＋項目一致＋全文一致） |
| `matching.py` | 案件 × 補助金・法令のマッチング（理由付き） |
| `external_api.py` | Jグランツ API・法令API v2 の取得 |
| `attribution.py` | **出典表示の部品（v0.2で新規）** |
| `seed_data.py` | デモ案件 |

## 3. v0.2 の変更点（出典表示への対応）
| # | 変更 | 対応する規約 |
|---|---|---|
| 1 | 補助金・法令の各カードに「出典：〇〇（原文ページへのリンク）（取得日）」を表示 | 出典の記載 |
| 2 | 補助金・法令の各セクションの最後に、出典・**加工した旨と加工の主体**・加工内容・利用規約へのリンクを表示 | 加工した場合の記載 |
| 3 | Jグランツは規約の記載例どおりの文言（「政府及び自治体によって保証されたものではありません」）を表示 | 国が作成したように見せない |
| 4 | スコア・理由・適格性に「本アプリの判定」と明記 | 加工部分と原情報の区別 |
| 5 | サイドバーとフッターに出典・利用規約の一覧を表示 | 出典の記載 |
| 6 | デモデータには出典を付けず「デモ（架空）」と表示（URLも空に変更） | 架空の情報を政府の情報に見せない |
| 7 | API呼び出しの間隔を0.2秒空ける | 短時間の大量アクセス禁止・10回/秒の上限 |

文言は `config.py` の `ATTRIBUTION` で一括変更できます。

## 4. 類似案件検索のロジック
```
スコア = 0.6×コサイン類似度（TF-IDF・文字2〜3gram）+ 0.25×項目一致率 + 0.15×全文一致（FTS5 trigram）
```
受注・失注それぞれ上位N件を左右に並べ、8項目の最頻値を比べて違う項目に色を付けます。

## 5. 補助金・法令のマッチングロジック
| 段階 | やること | 答える問い | 重み |
|---|---|---|---|
| ① 辞書ルール | 選んだ課題・機種・業種 → 検索語と理由文（`POLICY_DICT`） | なぜ関係するか | 0.4 |
| ② 内容類似 | 案件条件と補助金本文・条文のコサイン類似度 | 辞書にない関連も拾う | 0.3 |
| ③ 適格性 | 受付期間・対象地域・従業員規模・業種を照合 | 実際に使えるか | 0.3 |

- 受付終了・地域外・規模外は ×0.3 で下位に表示し「❌ 対象外の可能性」と表示
- 似た失注案件の敗因が「価格」「補助金・資金計画」なら「補助金で実質負担を下げる提案が有効」を理由に追加
- 法令は「追い風（提案材料）」「要確認（リスク説明）」に分類

## 6. 残っている課題
1. `POLICY_DICT` を営業・補助金担当へのヒアリングで充実させる
2. 補助金取得を夜間バッチにし、締切が近いものを通知する
3. 拠点ごとの日報・失注記録をCSV化して取り込む
4. AI（最終形）：自由記述から要因カテゴリ候補の提示、勝因・敗因の要約
5. 提案書を外部（顧客）に出す場合も、補助金・法令情報を載せるなら同じ出典・加工表示を入れる
